# Подключение Supabase и запуск

## 1. Создать проект
1. https://supabase.com → New project. Регион выберите ближе к Узбекистану (например, Frankfurt). Сохраните пароль БД.
2. Project Settings → API: скопируйте **Project URL**, **anon key**, **service_role key**.
   `service_role` секретный. Он нужен только серверу (cron), в браузер и в git его не кладите.

## 2. Применить миграции
Вариант A, через CLI (рекомендуется):
```bash
npm install
npx supabase login
npx supabase link --project-ref <PROJECT_REF>
npx supabase db push          # применит supabase/migrations/0001…0005
```
Вариант B, вручную: SQL Editor → по очереди выполнить файлы `0001…0005` из `supabase/migrations`.

Тарифы 60 000 и 85 000 создаёт `0005_seed.sql`. Менять их можно позже в админке.

## 3. Авторизация по телефону
Authentication → Providers → **Phone**: включить.
SMS-провайдер (Twilio, MessageBird, Vonage или другой из списка) нужен для боевой работы: подтверждение номера и восстановление доступа идут через SMS-код. Узбекские номера (+998) проверьте у выбранного провайдера, так как поддержка и цены различаются.
Для первых тестов без SMS можно отключить подтверждение (`Confirm phone`), но в продакшене это нужно включить.
Authentication → URL Configuration: укажите Site URL и адреса редиректа вашего домена.
Authentication → Rate limits и Password strength: поставьте минимум 8 символов.

## 4. Назначить главного администратора
1. Зарегистрируйтесь в приложении своим номером.
2. SQL Editor:
```sql
update public.profiles set role = 'admin' where phone = '+998XXXXXXXXX';
```
Только так: через API роль изменить нельзя. Админ-аккаунту магазин не нужен.

## 5. Realtime и Storage
Миграция `0003` уже добавила таблицы в `supabase_realtime`. Миграция `0004` создала три приватных бакета и политики. Проверьте во вкладке Storage.

## 6. Переменные окружения
```bash
cp .env.example .env.local   # заполните URL, ключи, CRON_SECRET (openssl rand -hex 32)
npm run dev                   # http://localhost:3000
```

## 7. Проверка безопасности (обязательно перед запуском)
Локально:
```bash
npx supabase start            # поднимет локальный Postgres, выведет DB URL
npx supabase db reset         # применит миграции
export LOCAL_DB_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres
npm run db:test               # должно напечатать: ALL TESTS PASSED
```
Тест проверяет изоляцию магазинов, запрет прямой записи в долги и платежи, неизменяемость платежей и аудита, невозможность повысить роль, блокировку магазина, истечение подписки и права чата. Не запускайте его на боевой базе.

## 8. Публикация (Vercel)
1. Залейте проект в GitHub → Vercel → Import.
2. Environment Variables: все из `.env.example`.
3. `vercel.json` уже содержит cron `/api/cron/daily` (раз в сутки). Vercel сам добавит `Authorization: Bearer $CRON_SECRET`, если переменная `CRON_SECRET` задана.
4. Домены: основной (например `app.qarzdaftar.uz`) и админский (`admin.qarzdaftar.uz`) добавьте к одному проекту. В `ADMIN_HOST` укажите админский хост: корень будет открывать `/admin`. Вход в админку защищён ролью, а не секретностью адреса.
5. Только HTTPS: без него PWA и service worker не работают.

Альтернатива cron на стороне Supabase (pg_cron):
```sql
select cron.schedule('qd-daily', '0 3 * * *',
  $$ select public.expire_subscriptions(); select public.generate_due_notifications(); $$);
```

## 9. Установка PWA
- **iPhone**: открыть сайт в Safari → «Поделиться» → «На экран Домой». Иконка и режим без адресной строки уже настроены. Заставка iOS появится после добавления картинок `apple-touch-startup-image` (например, генератором `pwa-asset-generator`).
- **Samsung/Android**: Chrome → меню → «Установить приложение». Заставку Android формирует из иконки и цвета фона манифеста.
- **Windows/Mac**: значок установки в адресной строке Chrome или Edge.
Push-уведомления при закрытом приложении не реализованы: сейчас уведомления хранятся в базе и приходят через Realtime. Web Push можно добавить следующим этапом (на iOS работает только для установленной PWA).

## 10. Управление платформой
- **Новый магазин** появляется в `Doʻkonlar` со статусом `pending`.
- **Оплата**: магазин присылает заявку, вы сверяете перевод и нажимаете «Подтвердить» (`Check`). Магазин активируется, подписка идёт от текущего момента или от конца действующей.
- **Блокировка**: статус `blocked` с причиной. Данные магазина остаются, запись закрыта, чат поддержки работает.
- **Тарифы**: цены и сроки меняются в `Obunalar/Tariflar`, старые подписки сохраняют прежнюю цену.
- **Аудит**: `audit_logs` фиксирует кто, что и когда изменил (до и после).
- **Резервные копии**: включите Point-in-Time Recovery или ежедневные бэкапы в Supabase (зависит от тарифа).

## 11. Чек-лист перед боевым запуском
- [ ] Подключён SMS-провайдер, подтверждение телефона включено
- [ ] `npm run db:test` проходит на локальной копии миграций
- [ ] `service_role` задан только в серверных переменных Vercel
- [ ] Администратор назначен, лишние тестовые аккаунты удалены
- [ ] Бэкапы включены
- [ ] Проверка с двух аккаунтов: магазин A не видит данные магазина B
- [ ] Юридическая сторона: политика конфиденциальности и согласие на хранение персональных данных клиентов (требования Узбекистана к персональным данным уточните у юриста)
